전력·자동 잠금 수정 QA 보고서

날짜: 2026-10-11
기준 버전: 1.5.3
상태: 사용자 실기기 QA 통과

변경 사항

  • 앱이 inactive 또는 background로 전환되면 화면 자동 잠금 억제를 즉시 해제합니다.
  • foreground로 돌아온 뒤에도 실행 중인 미터에 한해서만 화면 유지가 다시 활성화됩니다.
  • background 주행은 계속 기록하되, 정차 시 iOS의 위치 자동 일시정지를 허용하고 GPS 신호 손실 확인 주기를 1초에서 15초로 낮춥니다.
  • 주행 종료 후 background location execution을 해제하고, background의 30초 무이동 타이머는 예약 알림으로 대체합니다.

자동 확인

  • iOS Simulator Debug 빌드 성공
  • 명령: xcodebuild -quiet -project HoguMeter.xcodeproj -scheme HoguMeter -sdk iphonesimulator -configuration Debug -destination 'generic/platform=iOS Simulator' -derivedDataPath /private/tmp/hogumeter-derived build CODE_SIGNING_ALLOWED=NO
  • 정적 검토: iOS lifecycle·성능·QA 관점의 독립 검토를 완료했습니다.

수동 QA

  1. iPhone의 자동 잠금을 30초로 설정합니다. 미터를 시작하고 foreground에서 35초 대기합니다. 예상: 화면이 유지됩니다.
  2. 미터 실행 중 Home으로 나가거나 기기를 잠근 뒤 35초 대기합니다. 예상: 시스템이 정상적으로 잠길 수 있고, 앱은 background 위치 추적을 유지합니다.
  3. 앱으로 돌아옵니다. 예상: 실행 중인 미터만 다시 화면 유지 상태가 되며 거리·경과 시간이 연속됩니다.
  4. iPhone 설정의 자동 잠금을 30초로 설정한 뒤, 미터를 종료 또는 리셋하고 손을 떼고 75~90초 대기합니다. 예상: 화면이 정상 자동 잠금됩니다. 이 변경은 화면을 강제로 끄는 것이 아니라 iOS의 Auto-Lock 설정을 허용합니다.
  5. Always 위치 권한을 허용한 상태로 실제 이동 중 10분 foreground → 10분 background → 10분 foreground를 수행합니다. 예상: 거리와 시간이 단조 증가하고, 종료 뒤 위치 사용 표시가 사라집니다.
  6. 가능하면 동일 기기·밝기·네트워크 조건에서 Release 빌드의 Energy Log를 수정 전과 비교합니다. 예상: background 정차 상태의 wakeup과 에너지 영향이 감소하며, serious/critical thermal state가 발생하지 않습니다.

알려진 한계

  • 실제 자동 잠금, GPS 정확도, 열 상태는 실기기 및 주행 환경에 좌우되므로 시뮬레이터 빌드만으로 보증할 수 없습니다.
  • 이 수정은 주행 중 위치 정확도를 의도적으로 낮추지 않습니다. 고속 애니메이션·장거리 지도 렌더링의 추가 열 최적화는 별도 후속 작업입니다.
  • 다중 scene 환경의 process-global 화면 유지 정책은 장기적으로 coordinator로 분리하는 것이 바람직합니다.
